# ZANA Production Finalization

This document records the production finalization gate, identity security rules, and D1 migration handover procedures for the ZANA platform.

## 1. Release Gates

A production release is complete only when the GitHub Actions pipeline confirms all of the following:

- code validation, TypeScript checks, ESLint, unit tests, integration tests, architecture checks, security checks, and RTL checks pass;
- `migrations_production/` contains zero National ID references and applies cleanly against a fresh temporary D1 database;
- the Cloudflare Worker deploys successfully with `wrangler.production.json`;
- the live Worker revision matches the current Git commit;
- unauthenticated provider preflight access is rejected;
- authenticated provider preflight succeeds;
- production exposure checks and smoke tests pass;
- the release metadata job completes.

## 2. Production Architecture

- frontend: `https://zana.idggov.tech` on Cloudflare Static Assets (legacy domain: `https://zana.krd`);
- backend: Cloudflare Worker (`src/worker/index.ts`);
- Firebase: Authentication and Firestore only;
- no Firebase Hosting or Firebase Functions production deployment;
- no localhost or emulator production routing.

## 3. Authentication, Verified-Email & Student Isolation Rules

- **Verified Firebase Identity:** `verifyFirebaseIdToken` (`src/server/auth/tokenVerification.ts`) validates `RS256` signatures against Google JWKs and extracts `email_verified`. Test-mode JWT shortcuts are unconditionally disabled when `NODE_ENV=production` or `ZANA_ENV=production` and otherwise require explicit `ALLOW_TEST_AUTH_MOCK=true`.
- **Verified Subscription Email (`src/server/auth/verifiedEmail.ts`):** `resolveVerifiedSubscriptionEmail` accepts only cryptographically verified (`email_verified === true`), syntactically valid emails (including legitimate plus-addressing such as `user+tag@example.com`), and rejects synthetic `<uid>@zana.edu.krd` placeholders, phone numbers (`+...`), malformed dot patterns, and unverified client `body.email` / `body.studentEmail` values across onboarding, trials, status checks, admin student updates, and payment receipt submissions.
- **Email Verification & Registration/Onboarding:** Onboarding collects strictly **Full Name**, **Email**, and **School Name** (never National ID). Client-supplied `body.email` never overrides or falls back for verified token email. Email/password registrations trigger `sendVerificationEmail` and gate progression until `reloadAndCheckEmailVerified()` confirms `email_verified === true`; unverified email logins also prompt verification recovery cleanly instead of hitting hidden `403 EMAIL_NOT_VERIFIED` loops.
- **SMS / Phone Auth Out of Scope:** SMS and phone-based registration/login are unsupported in the current release (user-facing phone auth tabs removed in `Login.tsx` and `Register.tsx`; `/api/auth/phone/send-otp` fails closed with `503 SMS_PROVIDER_NOT_CONFIGURED`). Returning logins via `/api/trial/start` preserve existing `students.name`, `students.grade`, and `students.stream` when omitted.
- **UID Isolation & Cache Hygiene:** All student API routes scope reads/writes to the verified Firebase UID (`authResult.user.uid`) and return `Cache-Control: no-store`. Workbox `api-responses-cache` (`vite.config.ts`) caches only public `/api/health` and `/api/curriculum` routes, `/sw.js` serves with `public, max-age=0, must-revalidate`, and client storage clears cached profile/session-recovery data on logout or UID change.

## 4. Database & Migration Architecture

- **Historical `migrations/` (Local Compatibility):** Preserved completely unchanged for existing local `.wrangler` environments.
- **Production `migrations_production/`:** Used by `wrangler.production.json` (generated by `scripts/resolve-kv.js` with `"migrations_dir": "./migrations_production"`) and validated by CI (`Verify Production D1 Migrations`).
  - `0001`–`0008`: Exact copies of `migrations/0001`–`0008`.
  - `0009_student_onboarding_school_name.sql`: Adds `school_name` to `students` and `users` without any `national_id_*` columns or indexes.
  - `0010_email_uniqueness_and_registration_persistence.sql`: Enforces normalized email uniqueness while excluding only the exact `0006` synthetic address (`LOWER(TRIM(u.id || '@zana.edu.krd'))`), preserving legitimate `@zana.edu.krd` addresses, `NULL`s, orphaned subscriptions, admin roles, and trial timestamps.

## 5. Temporary D1 Verification Procedure

1. Keep `.wrangler` untouched; stage a temporary config in `/tmp/` pointing `migrations_dir` to the absolute path of `migrations_production/` and pass `--persist-to /tmp/<dir>`.
2. **Restored-backup check:** Load the verified remote export into the temp DB, reconcile `0006` and `0007` in `d1_migrations`, run `npx wrangler d1 migrations apply DB --local`, and assert before/after record parity, `role = 'admin'`, `NULL` placeholder/orphan emails, `school_name` presence, and `0` National ID objects.
3. **Fresh DB check:** Apply `0001`–`0010` from scratch into a separate `--persist-to` directory and verify `d1_migrations = 11`, `0` National ID objects, and `school_name` columns.

## 6. Production Migration Prerequisites, Rollback & Known Limitations

- **Prerequisites:**
  1. Capture and verify a fresh remote D1 backup SQL file (stored locally outside Git tracking via `.gitignore`).
  2. Explicitly authorize controlled reconciliation of `0006_users_and_curriculum_pages.sql` and `0007_payment_receipts.sql` in production `d1_migrations` (proven field-by-field identical in production; avoids re-running `0006`'s `INSERT OR REPLACE`, which would reset the admin user's `role` to `'student'`).
  3. Generate `wrangler.production.json` via `scripts/resolve-kv.js` so `migrations_dir` targets `./migrations_production`, then run `npx wrangler d1 migrations apply DB --remote --config wrangler.production.json` before `wrangler deploy`.
- **Rollback Limitations:** SQLite/D1 migrations are forward-only; `ALTER TABLE ADD COLUMN` and unique index data normalizations do not have automatic down-migrations. Recovery requires Cloudflare D1 Time Travel (`wrangler d1 time-travel restore`) or restoring the verified `.sql` backup, plus `wrangler rollback` for the Worker bundle.
- **Known Limitations:**
  - Existing local `.wrangler` dev databases that previously ran `migrations/0009_student_onboarding_national_id.sql` retain legacy `national_id_*` columns locally unless manually reset against `migrations_production/`.
  - Production currently holds 8 historical orphaned `subscriptions` rows (no matching `students`/`users` row); they intentionally retain `email = NULL` and unaffected trial state.
  - Phone-only onboarding via `/api/student/onboard` requires a verified email under current product rules; phone OTP remains fail-closed (`503`) until an SMS provider is configured.
